01TechCrunch / Hacker News · 919 分 / 814 评

微软高管在一份法庭文件中把 AI 抓取称为「人类历史上最大的劳动盗窃」

TechCrunch 基于一批未删节的法庭文件报道称，微软一位高管曾把 AI 抓取行为形容为「人类历史上最大的劳动盗窃」。报道的重点是这句表述被写进了法律文件，而不是某次公开演讲里的即兴修辞，这条帖子在 Hacker News 上拿到 919 分、814 条评论，是本期热度第二高的内容。

对做 AI 产品的人来说，这句话的价值在于它透露了一家公司内部对「训练数据从哪来」的真实态度：对外讲合作与授权，在内部沟通和法律文件里则用盗窃来定性。这意味着内容方在授权谈判里拿到的筹码正在变化，争议焦点从「你抓了我多少页」转向「你内部怎么描述这件事」。同一批素材里，面向 AI 的抓取基础设施仍在 GitHub 高星榜单上，能力与合规成本会同时抬升。

为什么值得关心：如果你正在做依赖公开网页内容的检索增强或 Agent 产品，这条决定了未来两年的成本结构：数据获取不再是默认免费，要么付费授权，要么有清晰可核验的合规路径。建议现在就把「内容来源成本」写进单位经济模型，而不是等法务来叫停。

02CNN / Hacker News · 498 分 / 377 评

美军因采用 AI 生成的幻觉情报报告出现险情

CNN 报道称，美军在一次行动中出现险情，原因是使用了一份由 AI 生成、内容实为幻觉的情报报告，报道把这一事件与中国船只联系起来。帖子在 Hacker News 获得 498 分、377 条评论。事件的关键不在于模型答错了，而在于错误的输出在人工复核环节被原样采纳了。

这是 设计失效的典型案例：只要复核环节的默认动作是「确认」而不是「独立验证」，人工介入就形同虚设。产品层面需要把置信度、来源引用和「未经验证」的状态做成显式信息，让复核者必须主动做出判断，而不是被动地点过。

为什么值得关心：高风险行业的客户会拿这类新闻来问你：出错了谁负责、系统怎么提示。可操作的判断是把「模型不确定时如何呈现」当成一等功能来设计，并在商务条款里明确 AI 输出的参考定位——这既是合规问题，也决定了产品能不能进入政企、医疗、金融这些行业。

04Claude Code 官方更新日志 / Hacker News · 714 分 / 266 评

Claude Code 在没有配置文件时改为读取 AGENTS.md

的更新日志显示，它现在会在项目里找不到 CLAUDE.md 时改为读取 AGENTS.md。这条变化在 Hacker News 上拿到 714 分、266 条评论，讨论集中在「项目上下文配置是否应该跨工具统一」这一问题上。

对 AI 产品经理而言，这是一次标准收敛的信号：AGENTS.md 正在被多个编码 Agent 接受为共同约定，意味着团队写下的项目规范、命令约定和上下文说明有机会成为可移植资产，换工具时不必重写一遍。一份配置能喂多家 Agent，会明显降低多工具并用的迁移成本，也会削弱单一工具通过配置文件形成的锁定。

为什么值得关心：这直接关系到工具选型的逻辑：如果上下文配置可以跨运行环境复用，「选哪个 Agent」就从长期绑定问题降级为可替换的组件问题。建议把团队的项目上下文文档按 AGENTS.md 的约定维护起来，把这份资产留在自己手上，而不是留在某个工具的私有文件里。

05sockpuppet.org 长文 / Simon Willison 推荐 / Hacker News · 627 分 / 374 评

《如何用 LLM 写作》引发高热度讨论，分歧集中在作者角色与质量保证

一篇题为《如何用 LLM 写作》的长文在 Hacker News 拿到 627 分、374 条评论，同日 Simon Willison 也把它列为推荐阅读。评论规模本身说明分歧不小，讨论主要围绕 LLM 参与写作之后作者的角色怎么界定、质量由谁来保证。

对 AI 产品经理来说，更实际的问题是内部产出流程：PRD、周报、对外文案里哪些环节允许模型参与、参与到什么程度、谁对成稿负责。把这篇文章当作团队讨论的引子比直接照搬一套 SOP 更有效，因为写作类 AI 的效果高度依赖使用者的判断力，而判断力恰恰是最难写进流程文档的部分。

为什么值得关心：写作是 AI 产品经理每天做得最多的事，也是模型能力最容易被高估的环节。建议先在自己的文档流程里做两周小实验：明确哪些段落必须自己写、哪些可以交给模型起草，然后观察评审返工率的变化，而不是先给全团队定规矩。

Stars 119,653 增长 — 语言 Python 许可 Apache-2.0
这是把任意代码库连同文档、SQL schema、配置文件和 PDF 转成可查询知识图谱的工具，以 /graphify 技能的形式接入 、Cursor、 和 Gemini CLI。
不同它不做向量检索，而是用本地确定性的 解析建图，每条边都有解释，因此结果可复现、离线可跑，也不需要维护向量库。
