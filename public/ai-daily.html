Cloudflare 重构 DNS 缓存，省下 100TB 内存

Cloudflare 公开了它对 1.1.1.1 公共 DNS 服务的一次大规模内存优化。通过重新设计缓存条目的存储方式、去掉冗余字段，并针对真实流量分布做定制压缩，团队在保持命中率不降的前提下，节省了大约 100TB 的服务器内存。这个数字对一个基础设施服务商来说相当可观，折算成硬件成本是一笔不小的费用。

对 AI 产品经理来说，这个案例的价值在于「缓存优化」的通用思路：当你的服务规模大到一定程度，任何看似微小的数据布局改动都会被放大成千万级的成本差异。AI 产品中无论是检索缓存、上下文缓存还是向量索引，都存在类似的节省空间。这篇工程博客可以作为团队做容量规划和成本优化的参考，毕竟 100TB 意味着能少采购一批机器。

为什么值得关心：AI 服务的内存和计算成本是产品毛利的关键变量，Cloudflare 的方法展示了在保持服务质量的前提下压缩资源占用的一条可复制路径。

Debian 社区投票通过决议，允许负责任地使用生成式 AI

Debian 这个历史悠久的开源操作系统发行版，刚刚通过内部投票，允许在项目开发中「负责任地使用生成式 AI」。此前这类工具在 Debian 社区里多半是被排斥或模糊对待的。这次决议等于在开源社区内部竖起了一个新的默认姿态——不是拒绝，而是设定边界后的接受。

为什么值得关心：开源社区是 AI 开发工具的重要受众，他们的规范变化直接决定市场空间，产品策略要提前适配这类「社区合规」要求。

Graphify-Labs/graphify

代码知识图谱 Agent 技能
Stars 112,325 增长 — 语言 Python 许可 Apache-2.0
这是一个把代码库、文档、SQL Schema、配置文件等自动转换可查询知识图谱的工具，为 、Cursor、 等编码 Agent 提供 /graphify 技能。它基于本地确定的 AST 解析，而不是向量数据库。
不同完全本地确定性解析，每条关系可解释，不需要向量存储，因此结果可审计，这对企业代码环境很友好。
适合需要让 AI 编码助手深度理解大型代码库结构、并且愿意接受本地化处理的研发团队。
今天看它瞄准的是 Agent 对代码库的「结构理解」短板——光靠 RAG 检索片段不够，知识图谱是另一个解题方向。
注意目前广泛支持主流语言，但边缘语言和极端复杂的构建配置很可能存在解析缺口，需要先小范围验证。
