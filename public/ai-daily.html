美联航禁止 AI Agent 代替旅客订票

美联航明确表态，不接受 AI Agent 代替旅客完成订票。这条在 Hacker News 上评论数（688）超过分数（664），是典型的争议型热帖：一端认为航司在保护自己的舱位与定价体系，另一端认为这是在用条款阻挡用户已经习惯的自动化助手。素材未披露具体执行方式，是条款禁止、技术拦截还是事后追责，目前不能确认。

这是今年 Agent 产品最现实的一道墙：能力早就够了，卡点是「被服务方是否承认这笔请求」。做代订、代购、代办类 Agent 的团队，需要立刻把三个问题补进产品设计——请求用什么身份发出、出了纠纷责任归谁、目标平台的服务条款是否允许。这类边界不是靠更强的模型能绕过的，它更可能催生一层新的中间协议或授权机制，谁先把「合法代理身份」做成产品能力，谁就拿到入场券。

为什么值得关心：它把 Agent 商业化的真实瓶颈从「模型能不能做」挪到了「对方认不认」。如果你的路线图里有任何代替用户操作第三方系统的功能，这条就是一次提前预警：先确认目标平台条款与授权路径，再谈体验优化，否则做出来的功能随时会被一纸规则下架。

03Google 官方博客 / Simon Willison 博客 / Hacker News 热帖 · 555 分 / 157 评

Google 发布 Gemini 决策 API，把模型的判断变成可留痕的记录

Google 在开发者博客上发布 Gemini 决策 API（），Simon Willison 也单独写了一篇介绍。从命名和发布位置看，它瞄准的不是又一次模型能力升级，而是模型在具体环节做出判断时的那一层：把决策过程结构化地输出、记录下来，供后续查阅。素材没有给出接口字段与计费方式，具体能力边界需要看官方文档。

这件事的方向比细节更值得记：过去「决策日志」是每个做 的团队自己搭的一套东西，现在平台层开始把它内建。对产品经理意味着两件事——第一，Agent 上生产的前置条件（可审计、可回溯、出问题能复盘）正从自建能力变成基础设施，自研这层不再构成差异化；第二，如果平台能给出标准化的决策记录，采购方评估供应商时会开始问「你的每一次判断能不能给出依据」，这会变成新的准入项。

为什么值得关心：可解释性正在从合规成本变成产品功能。如果你的 Agent 面向企业客户，决策留痕迟早是采购清单上的一行；与其自建一套私有格式，不如尽早判断是否跟随平台标准，避免将来做一次昂贵的迁移。

对 AI 产品经理，这条的价值不在于站队，而在于提醒你换指标。评估编码类 AI 工具时，如果只看「生成速度」和「一次通过率」，几乎必然会高估收益，因为成本被推到了几个月后的维护阶段。更合理的做法是把返工率、缺陷密度、新人接手成本纳入同一张表，用季度维度而不是单次任务维度去算投入产出。同样的逻辑也适用于任何「AI 提效」的内部工具：省下的时间是不是真的省下了，要看下游有没有把成本接回去。

为什么值得关心：这直接决定你怎么给 AI 编码能力定价和写 ROI。如果下游维护成本上升而你在汇报里只呈现生成速度，第一次季度复盘就会被打回；提前把维护侧指标放进评估框架，既是自保，也是判断这类工具该买到什么程度、该在哪些模块禁用。

07Google 官方博客 / Hacker News 热帖 · 481 分 / 304 评

Google 发布 Gemini 4 Hydrogen 模型

Google 在官方博客发布 Gemini 4 Hydrogen，在 Hacker News 上获得 481 分、304 条讨论。素材只提供了发布页标题与链接，具体的上下文长度、定价、多模态覆盖范围和基准成绩均未在素材中出现，需要以官方页面为准，本条不做能力推断。

值得产品经理注意的不是这一版本身，而是节奏：头部模型厂商的版本间隔已经压缩到让「为某个版本做深度优化」变成高风险投入。如果你的产品架构把提示词、工具调用格式和评测集绑死在单一模型版本上，每次换代都是一次没有预算的迁移项目。更稳的做法是把 做成一层可切换的抽象，同时维护一套自己的回归评测集——换代时先用评测集跑一遍，用数据决定跟不跟，而不是用发布博客的热度决定。

为什么值得关心：版本节奏本身就是一个产品约束。它决定了你的评测体系和模型抽象层是不是必需品，也决定了团队会不会陷入「每次发布都要紧急适配」的被动状态。把换代变成一次跑分而不是一次重构，是这类团队最该先建的能力。

firecrawl/firecrawl

面向 Agent 的网页抓取与数据接入
Stars 201,311 增长 —（本期建立基线，明日起显示增量） 语言 TypeScript 许可 AGPL-3.0
这是一套给 供料的网页数据抓取与搜索基础设施，把站点内容抓下来、整理成模型可用的干净结构，覆盖抓取、搜索和批量处理等场景。
不同定位不是「爬虫工具」，而是 Agent 的数据层：它把抓取、清洗、检索串成一条链路，让 Agent 不必自己处理反爬、动态渲染和格式清洗这些脏活。
适合需要实时外部信息的产品，比如竞品监控、行业情报、销售线索补充、研究报告生成；也适合把网页内容作为 RAG 数据源但一直卡在清洗环节的团队。
今天看模型能力差距在收窄，「喂进去的数据质量」重新成为产品差异化的来源。数据接入层的选择会直接影响回答质量的上限，这一层正在被单独产品化。
注意AGPL-3.0 是需要认真对待的：如果你的产品以服务形式对外提供且修改了它的代码，可能触发开源义务，商用前务必让法务过一遍，或选择其商业授权。另外抓取行为本身涉及目标站点的条款与 robots 规则，合规风险自担。
